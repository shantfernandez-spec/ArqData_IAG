Conexión de IA y pruebas

Qué falta para conectar una IA real y cómo comprobar la solución del MVP.

✦
Estado actual: la IA es simulada

El botón de revisión usa reglas de ejemplo dentro del navegador. Para conectarlo a un modelo real se necesita un proveedor aprobado, una clave de API protegida y un servicio intermedio. No se deben enviar tickets ni documentos internos a una cuenta personal.

1Definir el caso de uso

La IA no resuelve todo el proceso. En el MVP ayuda a revisar si el ticket está completo y prepara un resumen o una pregunta de aclaración.

  1. Elegir una solicitud ficticia.
  2. Definir qué campos debe revisar, como descripción, entidad y campos requeridos.
  3. Definir qué debe entregar: faltantes, resumen, sugerencia y fuente.

2Preparar una conexión segura

La página web no debe llamar directamente al proveedor ni guardar la clave.

  1. El equipo autorizado elige el proveedor de IA.
  2. Se crea un servicio intermedio, por ejemplo con Google Apps Script para la demostración o en el entorno aprobado por BBVA para una implementación real.
  3. La clave se guarda en las propiedades seguras del servicio, nunca en este archivo HTML.
  4. La interfaz envía solo el ticket de prueba al servicio y recibe una respuesta estructurada.

3Conectar los estándares con RAG

RAG permite que el modelo consulte documentos pertinentes antes de sugerir una respuesta. Para una primera prueba no hace falta cargar documentos del banco.

  1. Usar un estándar ficticio o público y autorizado.
  2. Buscar el fragmento que corresponde al ticket.
  3. Enviar al modelo el ticket y ese fragmento.
  4. Mostrar en la interfaz la fuente que apoyó la sugerencia.

4Mostrar y controlar la respuesta

El resultado de IA debe indicar claramente qué encontró y qué no pudo confirmar.

  1. Mostrar campos faltantes o un resumen.
  2. Incluir referencia a la fuente consultada.
  3. Permitir que el especialista edite, acepte o descarte.
  4. Enviar la respuesta solo después de aprobación humana.

Pruebas de calidad de IA

Antes de las sesiones

Además de probar la interfaz con personas, el grupo revisa varios tickets ficticios con respuestas esperadas para ver si la IA ayuda correctamente.

Ticket incompletoDebe identificar los campos vacíos y pedirlos, sin inventarlos.
Ticket completoDebe resumirlo y sugerir una respuesta respaldada por el documento de prueba.
Fuente no encontradaDebe reconocer que no tiene información suficiente en lugar de inventar una regla.

La diferencia: las pruebas de IA revisan si la respuesta es correcta y está respaldada. Las pruebas con usuarios revisan si las personas pueden usar la plataforma y entienden sus controles. Se necesitan ambas para sustentar la propuesta.

Qué significa conectar la IA, en sencillo

El formulario prepara el ticket. Un servicio seguro lo envía al modelo y también le entrega el fragmento de estándar que encontró. El modelo devuelve una sugerencia y la fuente. La plataforma la muestra al especialista. El especialista decide qué hacer. En el trabajo del grupo, primero se presenta ese recorrido con datos ficticios y una respuesta simulada; una conexión real se implementaría solo con el proveedor y los permisos aprobados.

Por qué se incorpora IA generativa: una regla automática puede avisar que pasaron quince minutos o asignar según disponibilidad. La IA generativa se incorpora para interpretar solicitudes redactadas de distintas maneras, detectar qué explicación o campo falta y proponer una respuesta basada en estándares consultados. Así, cada tecnología resuelve una parte distinta del problema.
